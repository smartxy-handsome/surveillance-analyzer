## 问题 1：夜间静态误检（立柱/门框/反光被判为人）

**根因**：COCO 日间 RGB 域 vs 夜间红外域的域差距。时间确认（单帧即删）只能滤瞬态噪声，静态物体跨帧持续存在，无法用时间逻辑排除。

### 1A. 伪标签 + 域内微调（根修，推荐）
流程：
1. 写抽帧脚本，从既有素材均匀抽 500–2000 帧（覆盖不同时段/光照）
2. 用现网模型跑伪标签：只保留时间确认后的高置信框，导出 YOLO 训练格式（我们有现成框，不走 SAM）
3. **审核 UI 人工确认/修正**（见问题 2，一石三鸟）
4. yolov8m 微调（person + vehicle 类，冻结 backbone 可选，~50 epoch，4070S 上小时级）
5. 离线评测对比新旧模型，达标后替换

- 工作量：中（脚本 + 审核 UI + 微调/评测流水线）
- 收益：根除静态误检，夜间 recall 大概率同时提升
- 风险：审核需要用户配合；伪标签噪声需靠人工审核兜底
- 依赖：用户标注配合（与问题 2 共享同一次劳动）

### 1B. 截图二次核验（快赢，可与 1A 并行）
对每个 appearance 截图裁剪做"人 vs 非人"二次核验，失败只降级为"疑似"标记，**不删记录不影响 recall**：
- 零样本：CLIP/SigLIP 本地推理，prompt 对比 "person" vs "pole/reflection/structure"
- 或小分类器：用审核 UI 积累的确认/否决样本训练（几十张即可起步）

- 工作量：小–中
- 风险：零样本在夜间红外域效果不确定，需先实验再定；确定性低

### 1C. 背景建模否决（固定机位特有，不推荐单独用）
MOG2/帧差检测"从未变化的像素区域"，否决落在其中的检测框。
- 风险：**长时间静止的人会被误杀**，与"最高前提不漏人"冲突
- 若采用，只用于降级"疑似"标记，不做否决

### 1D. 接受现状 + 人工标记负样本（最低成本）
误检不删，在审核 UI 里人工标记，积累为微调负样本库，等以后微调一并解决。

## 问题 2：识别精度无量化数字

### 2A. 审核 UI + 基线标注 + 评估脚本（推荐）
做一个**记录复核界面**（列出全部截图/事件，人工一键"是/否"），一次劳动同时产出三样东西：
1. **真值基线** → 评估脚本用时间 IoU 匹配（MOT 风格，容差 = 采样间隔）算 event-level precision / recall / F1 + 边界误差统计
2. 问题 1A 的微调训练数据（确认 = 正样本，否决 = 负样本）
3. 问题 3C 的 ID 合并边界案例复核

- 工作量：脚本小、UI 中；用户标注 5–10 分钟素材
- 收益：之后每轮优化都有客观回归依据

### 2B. 不做真值，继续抽样目检（现状）
零成本，但每轮优化的结论都只能靠感觉。

## 问题 3：ID 合并边界案例 / 同人重识别

### 3A. BoT-SORT 原生 ReID（推荐，改动最小）
- 复制 `botsort.yaml` → `with_reid: True`，调 `appearance_thresh`（建议从 0.6 起实测）→ `model.track(tracker=...)`
- `model: auto` 模式直接用 YOLO 骨干特征做外观相似度，**无需额外 ReID 模型/依赖**
- ultralytics 升到最新 8.4.x（pyproject 已允许，需回归测试）
- 与现有 TrackAggregator 互补：上游 track_id 更稳 → 需要合并的碎片更少，现有 IoU+gap 合并机制保留作兜底

- 工作量：小（配置 + 调参 + 回归）
- 风险：夜间红外下外观区分度低（颜色失真），阈值需实测；无效则回退，损失小

### 3B. torchreid/OSNet 自定义嵌入（不推荐）
调研结论：非正规 pip 包（源码安装）、2022 年后不活跃、权重托管在 Google Drive。既然 3A 原生支持已存在，此路线无必要。

### 3C. 保持现状 + 边界案例人工复核
复核界面（2A）里顺带勾选"同一个人？是/否"，为将来的 ReID 调参积累判断依据。

## 问题 4：进出时间 ±0.17s 量化误差（3fps 采样）

### 4A. 二次精化采样（原设计，挂起中）
命中窗口的进/出边界 ±0.5s 内全帧解码 + 直接推理，找首/末帧有检测的时刻。误差 → ~±0.04s（1/25s）。
- 工作量：中；只扫窗口，计算增量小
- 收益：时间戳精度 8 倍提升

### 4B. 保持 3fps + 文档注明误差范围（零成本）
对监控记录场景 ±0.17s 通常无实际影响。

## 问题 7：仓库仅本地，无远程、无 CI

### 7A. GitHub 私有仓库 + Actions（推荐）
- 私有仓库免费 2000 分钟/月；Windows runner 2 倍计费，check.sh 四步一次约 20–30 计费分钟，每月几十次提交无压力
- `.pt`/`data/` 已 ignore，不会入库
- CI 跑 ruff + pytest + vitest + build（与 check.sh 相同）
- **需用户一次性配合**：GitHub 账号、创建私有仓库、配置推送凭证

### 7B. 本地计划任务定期跑 check.sh
无云端依赖，但没有远程备份，不算 CI。

- 工作量：小

## 问题 9：车牌识别跑 CPU

### 9A. onnxruntime-gpu（挂起，量级上来再做）
`uv remove onnxruntime && uv add onnxruntime-gpu`，torch cu121 的 CUDA 运行时可复用。Windows 上 DLL 兼容是常见坑，需实测。当前 OCR 是事件级（每车一次而非每帧一次），耗时占比很小。

### 9B. 批量化调度
OCR 移到流水线结束后统一批处理。收益有限。

### 9C. 保持现状（推荐）
当前量级无瓶颈。
